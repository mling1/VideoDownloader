# VideoDownloader

MSE 流媒体视频捕获与无损合成下载工具（Tampermonkey 油猴脚本）。

通过劫持 MediaSource Extension（MSE）的 `SourceBuffer.prototype.appendBuffer`，被动捕获网页播放器投喂的音视频 fMP4 分片，再用 mp4box.js 无损合成为**单个可正常播放、可拖动进度条、有声的 MP4 文件**。

## 功能特性

- **全站点通用**：只要网站使用 MSE 播放流媒体（B 站、腾讯视频、优酷、抖音等），均可捕获
- **原型级劫持**：直接劫持 `SourceBuffer.prototype.appendBuffer`，不依赖拦截 `addSourceBuffer`，注入稍晚也能稳定捕获分片
- **无损合成**：容器级 remux，不重新编码，画质音质无损；输出普通 MP4（非 fragmented），支持进度条拖动
- **音视频自动分类**：优先按 MIME 分类，缺失时通过 init segment 的 hdlr box 自动识别，最终兜底按数据大小区分
- **新流自动重置**：检测到新的 init segment（ftyp）自动清空旧缓存，切换视频不会新旧分片混杂
- **大跳转标红锁定**：向前大幅跳转（>15秒）或向后跳转超出已缓存范围时，片段数变红色并锁定，防止跳转后不连续内容混入导致音画不同步
- **完整捕获标橙锁定**：视频完整加载后，片段数变橙色并锁定，不再追加新分片，防止自动连播/重播内容混入
- **自动完整下载**：一键静音+16 倍速+隐藏画面对完整视频进行静默捕获，完成后自动合成下载；过程中可再次点击暂停取消，完成后恢复原来的播放倍数
- **倍速加速**：1×/2×/4× 短按切换，长按 16×，加速视频加载和捕获
- **跳至结尾**：一键跳到视频结尾，触发剩余分片加载（执行前自动标红锁定）
- **完整性检测**：下载前检测缓冲是否完整，不完整时文件名自动加「片段」后缀；大跳转后下载会弹出确认提示
- **合成失败兜底**：合成失败时提供弹窗（分开下载 / 在线完整下载 / 取消），显示完整性检测结果和错误信息
- **多 MediaSource 支持**：抖音等平台会预加载下一个视频，脚本只取最后一组音视频轨，确保下载当前正在播放的视频

## 安装

### 一键安装（推荐）

确保已安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展，然后点击下方链接，油猴会自动弹出安装界面：

👉 **[点击安装 VideoDownloader](https://raw.githubusercontent.com/mling1/VideoDownloader/main/VideoDownloader.user.js)**

### 手动安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展
2. 打开 Tampermonkey 管理面板 → 「添加新脚本」
3. 删除默认模板，将 `VideoDownloader.user.js` 的全部内容粘贴进去
4. `Ctrl+S` 保存
5. 打开任意使用 MSE 播放的视频网站，页面右上角会出现蓝色面板

## 使用说明

脚本安装后，打开视频网站，页面右上角会出现蓝色控制面板：

```
┌─────────────────────────┐
│   VideoDownloader        │
│  下载已捕获片段 (0)      │
│  [1×] [跳至结尾]         │
│  [自动完整下载]           │
│  [在线完整下载]           │
└─────────────────────────┘
```

### 1. 下载已捕获片段 (N)

**功能**：将当前已捕获的音视频分片无损合成为单个 MP4 并下载。

**使用场景**：
- 视频已经播放/缓冲了一部分，想下载当前已加载的部分
- 不想等完整加载，只要前面的片段

**使用方法**：
1. 打开视频，播放或缓冲一段时间（按钮上的数字会显示已捕获的分片数）
2. 点击「下载已捕获片段」
3. 等待合成完成，浏览器会自动下载 MP4 文件

**注意事项**：
- 如果视频**未完整加载**，下载的文件名会自动加 `_片段` 后缀，视频时长只有已加载的部分，可以正常播放
- 如果视频**已完整加载**，文件名没有后缀，是完整视频
- 合成需要加载 mp4box.js（约 500KB），首次使用可能需要等待几秒

### 2. 倍速按钮 (1× / 2× / 4×)

**功能**：切换视频播放速度，加速视频加载和分片捕获。

**使用方法**：
- **短按**：在 1× → 2× → 4× 之间循环切换
- **长按**：切换到 16×（极速加载）

**使用场景**：想快速缓冲完视频，然后用「下载已捕获片段」下载。

### 3. 跳至结尾

**功能**：一键跳到视频结尾，触发剩余分片的加载。

**使用场景**：视频缓冲到一半卡住了，想强制加载后面的分片。

**注意**：跳至结尾后，播放器会从结尾开始播放，已捕获的分片仍然保留。

### 4. 自动完整下载（推荐）

**功能**：一键完成「静音 → 16 倍速 → 隐藏画面 → 从头播放 → 完整捕获 → 自动合成 → 自动下载」全流程。

**使用方法**：
1. 打开视频页面（视频可以是暂停状态）
2. 点击「自动完整下载」
3. 视频会自动静音并以 16 倍速播放（画面隐藏，不影响你做其他事）
4. 等待播放完成，脚本会自动合成并下载完整 MP4

**优点**：
- 不需要手动操作，一键完成
- 静音+隐藏画面，不打扰你使用电脑
- 16 倍速加速，比正常播放快很多
- 确保完整捕获，下载的是完整视频

**注意事项**：
- 播放过程中不要关闭页面或切换到其他视频
- 如果网站有自动连播（如 B 站播完自动跳下一个），可能会影响捕获，建议在播放完成后立即查看下载结果
- 部分网站对 16 倍速有限制，可能无法达到 16 倍

### 5. 在线完整下载

**功能**：跳转到在线工具页面，用于处理脚本无法自动合成的特殊视频流（如 m3u8 流、特殊编码）。

**使用场景**：
- 脚本合成失败，弹窗里选择「在线完整下载」
- 视频使用 m3u8 格式（非 MSE），脚本无法捕获
- 特殊编码的视频流，mp4box 无法解析

**使用方法**：点击后会在新标签页打开在线工具，按照工具页面的提示操作即可。

### 合成失败后的处理

如果合成失败（如最后一个分片不完整、特殊编码等），会弹出三选项弹窗：

```
┌─────────────────────────────┐
│       视频合成失败            │
│  ⚠️ 视频未完整加载            │
│  错误信息：xxx               │
│                             │
│  [分开下载] [在线完整下载] [取消] │
└─────────────────────────────┘
```

- **分开下载**：分别下载视频文件和音频文件（两个文件，需要自行用其他工具合并）
- **在线完整下载**：跳转到在线工具页面处理
- **取消**：关闭弹窗，不下载

## 常见问题 (FAQ)

### Q: 打开视频后面板不显示？
A: 
1. 确认油猴脚本已启用（油猴图标 → 已安装脚本 → VideoDownloader 开关打开）
2. 确认网站使用 MSE 播放（大部分视频网站都是）
3. 刷新页面重试
4. 检查是否被其他广告拦截扩展屏蔽

### Q: 按钮显示「下载已捕获片段 (0)」，捕获不到分片？
A:
1. 刷新页面，让脚本在页面加载时就注入
2. 点击播放视频，分片会在播放过程中逐步捕获
3. 如果刷新后仍然为 0，可能是网站使用了特殊的播放技术（如 WebRTC），脚本不支持

### Q: 下载的视频没有声音？
A:
1. 确认视频播放时本身有声音（不是静音状态）
2. 尝试用「自动完整下载」从头完整捕获
3. 如果仍然没声音，可能是特殊音频编码，尝试「在线完整下载」

### Q: 下载的视频无法拖动进度条？
A: 脚本输出的是普通 MP4（非 fragmented），正常情况下支持进度条拖动。如果无法拖动，可能是：
1. 下载的是不完整片段（文件名带 `_片段`），部分播放器对不完整 MP4 的 seek 支持不好
2. 尝试用「自动完整下载」获取完整视频

### Q: 下载的文件打不开？
A:
1. 确认下载完成（文件大小不为 0）
2. 尝试用 VLC 播放器打开（VLC 对不完整/特殊编码的支持更好）
3. 如果是分开下载的视频和音频，需要自行合并后才能正常播放

### Q: 自动完整下载没反应？
A:
1. 确认页面上有 video 元素（视频已加载）
2. 部分浏览器要求用户先与页面交互才能自动播放，先手动点击一下视频再点「自动完整下载」
3. 检查控制台是否有报错（F12 → Console）

### Q: 支持哪些网站？
A: 所有使用 MSE（Media Source Extensions）播放流媒体的网站，包括但不限于：
- B 站 (bilibili.com)
- 腾讯视频
- 优酷
- 爱奇艺
- YouTube（部分）

不支持：纯 m3u8 直链播放、WebRTC 直播、DRM 加密视频。

## 技术原理

1. **捕获层**：`document-start` 注入，劫持 `SourceBuffer.prototype.appendBuffer` 原型方法，将每次投喂的 fMP4 分片复制保存。用 `WeakMap` 建立 SourceBuffer 实例→{mime, buffers, kind} 映射。
2. **分类层**：优先按 `addSourceBuffer` 传入的 MIME 分类音视频；MIME 缺失时通过解析 init segment（ftyp+moov）中第一个 track hdlr box 的 handler_type（`vide`/`soun`）自动识别。
3. **合成层**：用 mp4box.js 分别解析音视频 fMP4 流，提取所有样本（sample），手动构建普通 MP4 的 sample table（stts/stsc/stsz/stco/stss），将所有样本数据拼入单个 mdat，输出非 fragmented MP4。
4. **容错处理**：喂数据前截断不完整的末尾 box（视频结束时最后一个 moof 可能被截断）；mp4box 解析错误时不直接失败，用已解析的样本继续完成合成。
5. **关键修复**：音频轨必须显式设置 `tkhd.volume=1`（mp4box addTrack 默认 volume=0，会导致严格播放器无声）；视频轨补 stss 关键帧索引以支持 seek。
